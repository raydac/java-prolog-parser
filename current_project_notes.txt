## 1. Implementation Progress
- Fixed signed capital exponents, trailing list commas, missing structure arguments, numeric functors, `OpContainer.removeForType` size, tokenizer close rewind, and newline pushback column.
- Full `mvn22 test` passed after the fixes.

## 2. Architecture & Technical Discoveries
- Tokenizer is a per-character state machine. Operator scan uses `String` prefix lookups on every extension.
- `doReadChar()` is `synchronized` and calls `Reader.read()` one char at a time.
- Numbers are `BigInteger` / `BigDecimal`. `PrologNumeric.getType()` returns `TermType.ATOM`.
- Phrase parser builds an `AstItem` tree, then `convertToTermAndRelease`.
- Integer-to-float transition now stores `E` as `e`. A second exponent marker ends the number and is pushed back.
- `readStruct` returns null only for a real `f()`. A missing argument throws `PrologParserException`.
- `Tokenizer.close` on a `PushbackReader` unreads `insideCharBuffer` only.

## 3. Technical Debt & Refactoring
- Operator matching should be a trie (or first-char bitmap plus trie) so atoms do not allocate a `String` per character.
- Read chars from an internal buffer filled by `Reader.read(char[])`.
- ASCII class table for whitespace / letter / digit / upper.
- Parse integers through `long` and allocate `BigInteger` only on overflow.
- Copy `lastTokens` only when `getLastTokens()` is called.
- `calcDiffAndPushResultBack` still resets the column to 1 when a pushed operator fragment contains a newline. Operator text does not contain newlines today.
